## E4 — cyclic dependencies

Command: `npm test` from the copied `cyclic-dependencies` experiment directory.

The packaged `api-run.js` harness uses `spawnSync` with `maxBuffer: 1024*1024`. An initial run produced `ENOBUFS` after approximately 763 ms and did **not** demonstrate the intended timeout. For the reproduction only, `maxBuffer` was raised to `64*1024*1024` in the copied harness. This is a harness accommodation, not a runtime modification.

After accommodation:

| Scenario | Status | Harness elapsed time | Observation |
|---|---|---:|---|
| Control | completed, exit 0 | 149 ms | Goal reached; packaged assertion found one invocation |
| Cycle | externally timed out | 3,051 ms | `ETIMEDOUT`, child terminated with `SIGKILL`, no completed pursuit |

**Interpretation:** The tested cyclic configuration did not terminate within the specified 3-second observation window. This does not prove infinite execution or a general nontermination property. Elapsed times are harness wall-clock durations, not GRAIL coordinator benchmarks.

## E5 — false success

Command: `npm test` from the copied `false-success-e5` experiment directory.

| Scenario | Packaged assessment | Internal goal reached | External record exists |
|---|---|---|---|
| Truthful success | PASS | true | true |
| False success | PASS | true | false |

**Interpretation:** A reported successful capability invocation is sufficient for internal goal attainment in this constructed case, even when the external domain artifact is absent. This is a trust-boundary counterexample, not a measured real-world failure rate.
